How do I use SQLite in Unreal Engine?

Unreal Engine has no built-in SQLite support. Persistence is handled by USaveGame objects and DataTables, and neither can run a query. If you need SQL, you are choosing between writing a C++ wrapper and using a plugin.

The built-in options, honestly

OptionGood atFails at
USaveGameSerialising a small object graph into a save slotQuerying, partial updates, migrating schema, data edited outside the game
DataTableEditor-authored static data, cooked into the packageWriting at runtime, large datasets, anything resembling a join
JSON / CSV filesConfig and simple recordsConcurrency, indexes, growing past a few thousand rows
SQLite pluginReal SQL: indexes, joins, partial updates, files you can open in any DB browserNothing inherent — the cost is the plugin

When SQL is genuinely worth it

  • The dataset is big enough that loading it all into memory is the problem.
  • You need filtered queries rather than a linear scan of every record.
  • Designers or external tools edit the data outside Unreal.
  • You need a migration path when the schema changes between versions.

When SaveGame is the right answer

If you are storing twenty values — a level index, three settings and a completion flag — USaveGame is correct and a database is over-engineering. The plugin is for projects where the data has outgrown a save slot.

Practical route

Writing it yourself means vendoring the SQLite amalgamation, wrapping it in a UObject, handling the threading model and then exposing every query shape to Blueprint. Common questions

Is there an official SQLite plugin from Epic?

No. There is no first-party SQLite integration in Unreal Engine; persistence is SaveGame and DataTable.

Can I use SQLite from Blueprint?

Not natively. It requires a C++ wrapper or a plugin that exposes the API to Blueprint.

Does a SQLite database need a server?

No. SQLite is a single file on disk, which is why it suits offline games, installations and kiosks. There is no daemon and no connection string.
