How do I open a second window in Unreal Engine?

You cannot open a second game window from Blueprint. Unreal renders one viewport per window, and a second window requires a second GameViewportClient created in C++. The engine exposes no node, setting or project option that spawns one.

What the engine gives you

OptionWhat you getLimit
Play → Standalone / New Editor WindowA separate window for the gameOne game window. The editor window is editor-only and never ships.
-windowed -resx -resyA resizable game windowStill one window, one camera.
nDisplayPer-display viewports across a clusterBuilt for fixed installations with config files; the views come from one camera rig, not from independent cameras at runtime.
Second machineA genuinely independent viewA second PC, a second build, and a state-sync layer you now own forever.

What a second window actually requires

In C++ the shape of the work is: subclass UGameViewportClient, create an SViewport inside a new SWindow through FSlateApplication::Get().AddWindow(), bind the two together, then drive each viewport's player controller and camera independently. It is roughly a week of engine work before it behaves correctly with input routing, DPI scaling and fullscreen transitions — and it has to be redone whenever the Slate layer changes.

The three places this breaks in practice

  • PIE is not the packaged build. In the editor the game is a child window; packaged, it is a top-level OS window with a different DPI path and its own fullscreen state. Code that works in PIE routinely fails after packaging.
  • Display indices are not stable. Saving “monitor 2” breaks the moment someone swaps a cable or docks a laptop. Persist an EDID-based device identifier instead, and add a fallback.
  • Each window is a full render pass. Cost scales with the number of cameras, not the number of monitors. A second view is typically 40–70% of the first, not 5%.

Common questions

Can I open a second window in Blueprint only?

No. There is no Blueprint node that creates a game window. Every route — C++, nDisplay or a plugin — ultimately creates an additional viewport client in native code.

Does the editor's “New Editor Window” help?

Only inside the editor. It cannot be used in a packaged build, so it is not a shipping solution.

Does a second window mean a second copy of the game?

No, if it is implemented as an additional viewport in the same process. Both windows share one game state, which is the entire reason to do it this way instead of adding a second PC.
